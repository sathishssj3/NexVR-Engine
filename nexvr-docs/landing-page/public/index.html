What happens per frame

Six stages, one frame.

The game never knows it is being watched. NexVR detours the swapchain, finds the camera on its own, and rebuilds the frame in stereo before the game's own present call ever returns.

  1. Present() hooked

    A MinHook detour lands on the swapchain's present call. One hook manager owns the whole lifecycle — installation, trampolines and teardown — so nothing is left patched in the process on exit.

    HookManagerMH_InitializeIDXGISwapChain::PresentvkQueuePresentKHR

  2. Backbuffer acquired

    The lifecycle manager validates the epoch and pulls the live backbuffer — the exact surface the game was about to show your monitor. A resize or a device reset bumps the epoch, and every cached view is dropped rather than reused.

    Dx11LifecycleManagerDx12LifecycleManagerVulkanLifecycleManager

  3. View matrix locked

    Candidate matrices are collected from constant buffers and scored until the real view and projection lock in. Scoring is what makes this general: no per-game patching, no hex editing, no signature that breaks on the next update.

    CandidateCollectorCameraLockManager

  4. Depth reconstructed

    The depth buffer is identified the same way — candidates in, scored, locked. Depth is what turns a flat image into geometry your eyes can actually converge on. Without it both eyes receive almost the same picture and the scene reads as a photograph.

    DepthCandidateCollectorDepthLockManager

  5. Stereo pair warped

    Compute shaders reproject the frame into a left and a right eye, then fill the disocclusions that reprojection opens up along every silhouette edge — the slivers of world that one eye can see and the other never had pixels for.

    FrameCoordinatorReprojection CSDisocclusion fill

  6. Submitted to OpenXR

    Both eyes go to your runtime — SteamVR, Meta Quest Link, WMR — in the runtime's own frame loop rather than on the game's clock. Depth ships alongside the colour layer so the runtime's spacewarp has something to reproject against when a frame runs late.

    xrWaitFramexrBeginFramexrEndFrameOpenXRFrameSubmitter

The deadline

11.1ms

At 90 Hz a frame is 1000 ÷ 90 milliseconds wide. Every stage above runs inside that window. Miss it and your headset shows you the last frame again — which your inner ear notices immediately.

Budget by refresh rate

  • 72 Hz13.9 ms
  • 80 Hz12.5 ms
  • 90 Hz11.1 ms
  • 120 Hz8.3 ms

The budget is the whole frame, not NexVR's share of it. The game still has to render inside the same window — which is why headroom on the flat game is the single best predictor of a comfortable result.

Three graphics APIs

One pipeline, three doors.

The six stages are the same everywhere. What changes is where the hook lands and what the API demands in return — DirectX 12 and Vulkan hand you explicit control of submission, and getting that ordering wrong is how an injector deadlocks a game instead of rendering it.

DirectX 11

DX11
  • Hook pointPresent · ResizeBuffers
  • ContextImmediate
  • StateSaved and restored
  • Resource accessDirect from swapchain

The forgiving one. The runtime manages submission, so the work is mostly state hygiene — capture what the game had bound, do the stereo pass, put it all back exactly as found.

DirectX 12

DX12
  • Hook pointPresent · Present1
  • QueueGame's main queue
  • OrderingSTRICT FIFO
  • BarriersExplicit transitions

Every stereo dispatch and copy is submitted to the game's own command queue rather than a private one. A second queue would race the game's rendering and tear; single-queue FIFO is the contract that keeps the frame coherent.

Vulkan

VK
  • Hook pointvkQueuePresentKHR
  • MechanismDispatch table
  • Untracked devicesPass-through
  • Recursion guardTRAMPOLINE

Resolution goes through the original vkGetDeviceProcAddr, never the hooked one — returning a patched pointer to a lookup for that same pointer is an infinite recursion. Devices created before injection are passed through untouched.

A wrapper that targets a game engine only works on that engine. Hooking at the API layer means the engine underneath — Unreal, Unity, RE Engine, something in-house — stops being a question the injector has to answer.

Before the lock

Never a black screen.

Stereo needs two locks: the view matrix and the depth buffer. Menus, loading screens, launchers and pre-rendered cutscenes often present neither — there is no camera in a main menu and nothing to reconstruct depth from.

The wrong answer is to stop submitting frames. A headset with no incoming frames goes black, the runtime starts warning about a lost session, and the user concludes the injector crashed. So when stereo is unavailable NexVR keeps submitting: the flat backbuffer is copied into both eye swapchain images, and you get the game on a screen in front of you instead of a void.

The transition into stereo is therefore something you see happen. The flat panel gains depth the moment both locks land — usually a second or two into actual gameplay.

StateWhat you seeWhy
No locks Flat frame, both eyes Menu or loading screen — no camera is being presented
Camera only Flat frame, both eyes View matrix found, depth not yet identified
Camera + depth Stereo, reprojected Both locks held — the full pipeline runs
Lock lost Falls back to flat Scene change or device reset invalidated the candidates

Shipped profiles

Tuned, not guessed.

Every game hands its matrices over differently. A profile records what that game does — depth direction, matrix order, colour space — so NexVR gets it right on the first launch instead of the fifth. These ship in the box.

Profiles are plain JSON in profiles/. Adding a game takes about three minutes and no C++. Game names are used only to identify compatibility; all trademarks belong to their respective owners, who are not affiliated with this project.

What the flags mean

Four questions per game.

Each flag is a convention the game chose and never documented. Guess wrong and the failure is specific and recognisable — which is what makes these worth reading before you file a bug.

reverseZ

Depth stored from 1 at the near plane to 0 at the far plane instead of the other way around — it buys back floating-point precision in the distance. Read it backwards and the world turns inside out: distant geometry converges in front of your face.

rowMajor

Which way the matrix is laid out in memory. Transposed against the game's actual convention, the extracted camera basis is wrong in a very visible way — the horizon tilts, or the view ends up rotated ninety degrees off.

srgb

Whether the backbuffer is already gamma-encoded by the time NexVR sees it. Apply the transform twice and the image washes out; skip one that was needed and the blacks crush and the midtones go muddy.

depth

Whether the depth buffer is submitted to OpenXR alongside the colour layer. Runtimes use it for spacewarp and late-stage reprojection, so submitting it is what keeps motion smooth when the GPU misses the deadline.

Writing one yourself

A profile is the seven fields the cards above are drawn from, and nothing else. Drop the file in profiles/ and restart the launcher — there is no build step, no registration list, and no C++.

An unprofiled game is not blocked. The matrix and depth search runs regardless; a profile just means the search starts from known-correct answers instead of converging on them. Unprofiled titles are more likely to lock slowly, lock wrong, or not lock at all. 

// profiles/palworld.json
{
  "name":     "Palworld",
  "engine":   "Unreal Engine 5",
  "api":      "DX12",
  "reverseZ": true,
  "rowMajor": true,
  "srgb":     true,
  "depth":    true
}

Comfort

Motion sickness is a bug.

Simulator sickness is a conflict, not a preference. Your eyes report motion; your inner ear reports none; the mismatch is read as poisoning and your body responds accordingly. A flat game converted to VR produces that conflict constantly, because the camera moves in ways no head ever does — mouse-look accelerations, scripted camera shake, cutscene pans, vehicle motion.

Two things help more than anything else, and neither is resolution. The first is holding the frame rate: a dropped frame in VR is not a stutter, it is the world briefly detaching from your head. The second is shrinking the field of view during motion, because peripheral vision is where optical flow is read most strongly.

Both are what the engine spends its comfort budget on — spacewarp for the first, a peripheral vignette that tightens under motion for the second.

TriggerWhy it hurtsMitigation
Dropped frames The world detaches from your head for a beat Spacewarp reprojection
Fast strafing Heavy optical flow across the periphery Vignette under motion
Camera shake Motion your neck never produced Turn it off in the game
Wrong depth Eyes fight to converge on a bad disparity Use a profile

Start with short sessions. Tolerance genuinely builds with exposure, and pushing through nausea is the one approach that reliably makes it worse.

!

Single-player only. This is enforced, not advised.

Injecting into a multiplayer game protected by Easy Anti-Cheat, BattlEye or Vanguard can get your account permanently banned. NexVR detects those systems and refuses to inject — there is no override switch and no flag to turn it off. Use it on single-player and unprotected titles.

It also will not attempt to defeat kernel-level anti-cheat, and it never will. That is a line the project does not cross.

Setup

Four steps, once.

01

Install

Run the Windows installer. It places the launcher, the injector DLL and all six shipped profiles. Nothing is installed into your games.

02

Open the launcher

It reads your Steam libraries from disk and lists the titles it recognises, along with which of them have a profile.

03

Start your runtime

Quest Link, SteamVR or WMR — whichever you already use. The active OpenXR runtime is detected from the registry, not asked for.

04

Pick a game and inject

Launch the game, then attach. Watch the log for the camera and depth locks; when both land, the flat panel resolves into stereo.

Attaching to an already-running game is the supported path. Injection is runtime — the DLL is loaded into the live process, no game files are modified, and closing the game unloads everything.

Troubleshooting

When it goes wrong.

Will this get my account banned?

On a single-player game with no anti-cheat there is nothing watching the process and nothing to ban. On a protected multiplayer game, injecting a DLL into the render pipeline is precisely the behaviour anti-cheat exists to catch — which is why NexVR refuses to attach to those processes at all. Treat any title shipping Easy Anti-Cheat, BattlEye or Vanguard as off-limits.

The game runs, but the headset shows it flat — like a cinema screen.

That is the passthrough fallback, working as designed. Stereo engages only once both the view matrix and the depth buffer are locked, and menus, loading screens and cutscenes frequently present neither. Rather than go black, the flat frame is copied into both eyes. Move into actual gameplay and it should converge within a second or two.

Everything looks like a photograph pasted at one distance.

The camera locked, depth did not. With no depth buffer there is nothing to reproject against, so both eyes receive nearly identical images and the scene has no volume.

Check the launcher log for the depth stage, and check whether the title has a shipped profile — depth in the profile is exactly this setting.

The world is inverted, tilted, or lying on its side.

Matrix convention mismatch. rowMajor controls whether the matrix is transposed before use; reverseZ controls whether the near and far planes are the way round the game expects. Both are per-game, and on an unprofiled title both are inferred rather than known.

Colours are washed out, or the blacks are crushed.

srgb. The backbuffer may already be gamma-encoded before NexVR ever sees it. Applying the transform a second time washes the image out; skipping one that was needed crushes it. One flag, two symptoms, opposite directions.

My game isn't in the list. Does it still work?

It may. Profiles are an accelerant, not a requirement — the matrix and depth search runs on every title. A profile means the search starts from known-correct answers instead of converging on them, so unprofiled games are more likely to lock slowly, lock wrong, or fail to lock.

If it works, the settings that made it work are a profile. Write them down and drop the JSON in profiles/.

Does it need an internet connection?

No. Injection, profile matching and OpenXR submission are entirely local. The launcher reads your Steam library from disk and your active runtime from the registry.

Why Windows only?

Two of the three backends are DirectX, and DirectX is Windows. The Vulkan path is portable in principle, but the launcher, the installer and the anti-cheat detection are not — and shipping a third of a product is worse than shipping none of it.

Will it run on my GPU?

Stereo asks for close to twice the pixels of the flat game. Reprojection and spacewarp absorb some of that cost, not all of it. The reliable predictor is headroom: if the game already runs comfortably above your headset's refresh rate on a flat monitor, you have somewhere to spend. If it barely holds 60, stereo will not rescue it.

Does it modify my game files?

No. The DLL is loaded into the running process at runtime and every hook is removed on exit — the hook manager owns installation and teardown as one lifecycle specifically so nothing is left patched behind. Closing the game returns it to exactly the state it shipped in.
