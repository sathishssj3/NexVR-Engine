# Security Policy

NexVR Engine implements several security measures to ensure safe and predictable injection behavior. 

## Implemented Security Checks

The injection engine (`vr-inject-cli.exe` and `vrinject.dll`) enforces the following validation layers:

1. **Origin Restriction (S3.3)**: Injection is gated by a secure environment variable token (`NEXVR_AUTH_TOKEN`) generated by the launcher. The injector also verifies that it was spawned by a trusted parent process (the Electron launcher) to prevent rogue invocations.
2. **Process Target Validation (S3.1)**: The target PID is verified. The injector ensures the target process is actively running and meets a minimum memory footprint threshold, avoiding injection into tiny launcher or helper processes.
3. **Path Traversal Protection (S1.2)**: Relative DLL paths or paths containing `..` are strictly blocked.
4. **PE Header Validation (S1.3)**: The target DLL is checked for a valid PE (MZ) header before injection.
5. **DLL Hash Verification (S1.4)**: At build time, a SHA-256 hash of `vrinject.dll` is computed and baked into the CLI. At runtime, the CLI verifies the payload DLL matches this exact hash to detect tampering.
6. **Anti-Cheat Protection (S3.4)**: The injector actively scans for known Anti-Cheat services (e.g., Easy Anti-Cheat, BattlEye, Vanguard) and strictly refuses to inject if detected.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it via private message to the repository maintainer. Do not disclose vulnerabilities publicly until they have been addressed.
